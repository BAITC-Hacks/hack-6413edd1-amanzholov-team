# Источники, решения MVP и ограничения

## Проверенные исходные материалы

В `frontend/public/data` найдены employees.json, skills.json, events.json и
activity_history.csv. Оболочки JSON соответствуют промту. Объёмы: 200/60/40,
32 role_profiles и 2743 строки истории. meta.as_of_date = 2026-10-01.
Оригинальный ZIP, README.ru.md и PDF отсутствуют; упаковка оригинального ZIP
не проверена. ZIP-парсер проверяется синтетическими архивами и поддерживает
вложенные каталоги. Исходные файлы сохранены без изменений.

Исходная лестница Junior/Middle/Senior/Lead сохраняется в framework Canonical.
Правило EV_036 помещено в адаптер импорта, преобразующий его в repeatable;
ядро прогрессии не знает внешнего ID. Отсутствующий навык в расчётах равен 0.
Дата history.date для completed — только legacy_proxy; до last_review_date
прирост уже включён в импортированную оценку. Будущие записи не участвуют.

## Явные синтетические расширения

Demo framework имеет Стажёр → Junior → Junior+ → Middle → Middle+ → Senior,
затем независимые Expert/Manager и горизонтальный переход к Data Engineer.
Требования заданы явно в demo.py, а не интерполяцией. Audience mapping:
Стажёр/Junior/Junior+ → Junior; Middle/Middle+ → Middle; Senior/Expert → Senior;
Manager → Lead. Версия mapping — версия framework/policy. Вакансия DEMO,
учебная лаборатория, пользователи и оценки полностью синтетические.

Для импортированного доверенного каталога независимое подтверждение завершения
считается достаточным основанием заданного gain; это политика адаптера MVP.
Для новых произвольных активностей grants_verified по умолчанию false.
Подтверждение опыта не повышает навыки. Отмена оценки/понижающая переоценка
не реализованы: обычная заявка не может понизить более высокий навык.

## Ограничения

Локальный demo-login — единственный адаптер идентификации. Production его
запрещает; корпоративный SSO предстоит интегрировать. Rate limiting действует
в одном процессе. Нет бинарных вложений, внешнего HRIS/LMS и отправки уведомлений.
Справочники создаются импортом и seed; отдельный CRUD всех политик и grants
не входит в HTTP MVP. Admin сам по себе не является оценщиком.

Импорт проходит проверки и применяет записи в одной откатываемой транзакции;
dry-run использует тот же путь с rollback. Ошибка сообщает первый нарушенный
инвариант, а не полный список всех ошибок пакета. Исходные payload не
публикуются; конфликты определяются хешем канонического содержимого записи.
У namespace одна неизменяемая дата среза; новая дата требует отдельного
пространства/БД. История без JSON требует пустую meta-оболочку employees.json.

Выборка списков ограничена HTTP-пагинацией, но реализация Store загружает
отфильтрованные записи перед срезом. Для значительно больших объёмов нужна
SQL-пагинация и специализированные HR-проекции. Показатели относятся к
целям и конкретным требованиям; не являются вероятностью найма и не вызывают
автоматических кадровых решений. Производительность нужно оценивать по
измерениям в этой среде, а не считать гарантией production.

Переводы названий каталога не создавались. UI locale сохранён; фиксированные
ошибки поддерживают ru/kk/en. Неизвестный code сопровождается локализованным
общим сообщением и машинным кодом причины. Доказательства не скачиваются.
