# Воспроизводимая демонстрация

Используйте чистую отдельную demo-БД, включите DEMO_SEED=true, задайте собственный
DEMO_PASSWORD в .env и выполните `docker compose up --build` из backend.
Seed повторяемый и не сбрасывает прогресс. Для повторения с нуля создайте другую
БД/Compose project; автоматического удаления рабочего volume нет.

```powershell
$env:DEMO_PASSWORD = 'YOUR_CONFIGURED_DEMO_PASSWORD'
./scripts/Demo.ps1
```

Скрипт входит как employee, reviewer и admin. Сотрудник заявляет Python 3,
admin назначает независимого оценщика, оценщик фиксирует наблюдавшийся уровень
2. Выбирается явно демонстрационная вакансия Junior+, сервер строит
рекомендацию лаборатории. Сотрудник записывается и отправляет доказательство
завершения. Reviewer подтверждает завершение. Скрипт сравнивает результат с
предварительной симуляцией, проверяет ready_for_review, сохранение официального
Junior и равенство карты после переключения Classic → RPG.

В запросах используются найденные через API идентификаторы и стабильные
Idempotency-Key. Проценты вычисляет сервер. Повтор после успешного завершения
выводит сохранённое состояние. Скрипт не повышает официальный грейд.

Примеры JSON-команд (UUID берутся из каталога):

```json
{"skill_id":"00000000-0000-0000-0000-000000000001","claimed_level":3,"evidence":"Описание выполненной работы"}
```

Рассмотрение назначенной заявки:

```json
{"decision":"approved","observed_level":2,"rubric":"Самостоятельное выполнение задания","rationale":"Наблюдался уровень 2"}
```

Конфликт версий возвращает 409 с code=profile_version_conflict. Неназначенный
оценщик получает 403, неизвестное поле/некорректный уровень — 422. Все ошибки
имеют request_id. OpenAPI с телами команд доступен по `/docs` и `/openapi.json`.
