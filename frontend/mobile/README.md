# Career Quest — кабинет сотрудника

Мобильный веб-интерфейс на React, TypeScript и Vite с режимами Classic и RPG.
Приложение подключено к тому же FastAPI и PostgreSQL, что и
[HR-кабинет](../README.md).

## Запуск

Из корня репозитория с настроенным `backend/.env`:

```powershell
./start.ps1
# Эквивалентная команда:
docker compose -f backend/compose.yaml up --build -d --wait
```

Откройте http://localhost:3000. Демонстрационный логин — `employee`,
пароль — значение `DEMO_PASSWORD` из `backend/.env`. Для создания demo-аккаунтов
нужны `DEMO_AUTH=true` и `DEMO_SEED=true`. Существующий `.env` сохраняйте;
начальная настройка описана в [корневом README](../../README.md).

Общий запуск поднимает PostgreSQL, миграции и импорт, API, HR-кабинет
на http://localhost:5173 и мобильный кабинет на http://localhost:3000.
Описание API доступно на http://localhost:8000/docs.

Для разработки нужен Node.js 24 и запущенный backend. Порт 3001 позволяет
работать одновременно с Docker-версией на порту 3000:

```powershell
cd frontend/mobile
npm ci
npm run dev -- --host 127.0.0.1 --port 3001
```

Откройте http://localhost:3001. Vite перенаправляет `/api` на
http://127.0.0.1:8000; в Docker запросы проксирует nginx.

## Сценарии

- После входа загружаются профиль, навыки, карьерная карта, заявления, записи
  на активности и заявки на завершение текущего сотрудника.
- Выбор Classic/RPG сохраняется в настройках на сервере и восстанавливается
  при следующем входе.
- Рекомендации рассчитывает сервер с учётом карьерной цели и текущих данных.
  При недоступности AI сервер использует расчёт по правилам.
- Навык для заявления выбирается из серверного каталога; сотрудник указывает
  заявленный уровень и evidence. Подтверждённый уровень меняется после оценки.
- Открытую вакансию можно выбрать как карьерную цель. Сопоставление требований
  и навыков выполняется сервером.
- Сотрудник записывается на активность и отправляет результат на подтверждение.
  Заявка остаётся ожидающей до решения независимого уполномоченного оценщика;
  само нажатие кнопки отправки не начисляет навыки.
- Запрос оценки для повышения проходит серверную проверку требований.
  Повышение требует отдельного решения HR.

Назначение оценщика, подтверждение результатов и решение о повышении доступны
через backend API соответствующим ролям. HR-кабинет работает в режиме просмотра.

## Подключение к API

`src/services/api.ts` отправляет запросы к `/api/v1`, передаёт токен
авторизации и ключи идемпотентности для изменяющих состояние команд.
Токен хранится в `sessionStorage` отдельно от сессии HR-кабинета.
`src/services/workspace.ts` собирает данные текущего пользователя через
`/me`, `/me/skills`, `/me/career-map`, `/me/skill-claims`, `/me/enrollments`
и `/me/completion-requests`, а также загружает каталоги и серверные рекомендации.
Списки загружаются с учётом пагинации.

Команды сохраняют изменения в общей PostgreSQL. После обновления данных
они доступны в HR-кабинете сотрудникам HR с соответствующим доступом
к подразделению. Импортированный профиль сам по себе не создаёт аккаунт:
для демонстрации используется отдельная учётная запись `employee`.

## Проверки

```powershell
npm test
npm run lint
npm run build
```

`lint` проверяет TypeScript без генерации файлов. Dockerfile выполняет
тесты, проверку TypeScript и сборку на Node.js 24 перед созданием nginx-образа.
