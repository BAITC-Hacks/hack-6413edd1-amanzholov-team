# Career Quest frontend

HR-кабинет на React, TypeScript и Vite. После входа приложение получает данные
из FastAPI: `GET /api/v1/hr/workspace`. Источник данных — PostgreSQL; сервер
ограничивает список сотрудников подразделениями, к которым у HR есть доступ.
Мобильный веб-интерфейс сотрудника находится в [`mobile`](mobile/README.md)
и использует тот же API и PostgreSQL. Это отдельное Vite-приложение.

## Запуск

Из корня репозитория с настроенным `backend/.env`:

```powershell
./start.ps1
# Эквивалентная команда:
docker compose -f backend/compose.yaml up --build -d --wait
```

Откройте http://localhost:5173. Для демонстрационного входа используйте логин
`hr` и значение `DEMO_PASSWORD` из `backend/.env`; должны быть включены
`DEMO_AUTH=true` и `DEMO_SEED=true`. API: http://localhost:8000/docs.
Настройка окружения описана в [корневом README](../README.md).
Общий запуск также поднимает кабинет сотрудника на http://localhost:3000
с демонстрационным логином `employee` и тем же `DEMO_PASSWORD`.

Для разработки UI запустите backend указанной командой, затем в другом терминале:

```powershell
cd frontend
npm install
npm run dev -- --port 5174
```

Vite будет доступен по http://localhost:5174 и перенаправит `/api` на
http://127.0.0.1:8000. В Docker запросы `/api` перенаправляет nginx.
Сборка: `npm run build`; проверка кода: `npm run lint`; тесты расчётов: `npm test` (Node.js 24). Docker выполняет эти проверки при сборке.

## Основные сценарии

- Откройте «Сотрудники»: поиск работает по имени, ID, должности и подразделению. Фильтры по подразделению, должности и грейду сочетаются с быстрыми фильтрами «С карьерной целью», «Без цели» и «В обучении».
- Карточки сводки показывают доступную HR команду; нажатие на показатель выбирает соответствующий фильтр. Обучение учитывает только `enrolled` и `in_progress` на дату среза, ожидающие подтверждения записи показаны отдельно.
- В каталоге видны целевая роль, соответствие по подтверждённым навыкам, зоны роста и активное обучение. Явная цель отделена от автоматически выбранного следующего грейда. Закрытая вакансия отмечена отдельно; отсутствие требований не отображается как 0%.
- Доступны сортировка по имени, соответствию цели и стажу, пагинация по 10 сотрудников и переход в профиль. Поиск, фильтры, сортировка и страница сохраняются в URL. На мобильном экране таблица отображается карточками.
- В профиле показаны навыки, разрывы относительно карьерной цели, карьерная цель, история участия и до трёх рекомендаций.
- Предварительные рекомендации рассчитываются в браузере по полученным данным: учитываются целевой грейд, critical skills, прирост навыка, prerequisites и предыдущие завершения/пропуски похожих активностей. Обязательные мероприятия не рекомендуются. Этот прогноз не создаёт серверный снимок рекомендаций и не изменяет оценки сотрудника.
- В «HR-аналитике» видны частые разрывы, участие по мероприятиям и сотрудники без доступного следующего шага.
- HR-кабинет работает в режиме просмотра. Завершение активностей и импорт из браузера недоступны; импорт выполняет администратор через backend API или CLI.

Токен сессии хранится в `sessionStorage`. Профили и история не сохраняются в
`localStorage`: повторная загрузка получает актуальные данные из API.
Подключение к API находится в `src/services/api.ts` и
`src/context/CareerDataContext.tsx`, предварительные расчёты — в
`src/services/careerData.ts`.

В мобильном кабинете рекомендации рассчитывает сервер; там доступны
заявления навыков, выбор вакансии как карьерной цели, запись на активности,
отправка результата и запрос оценки для повышения. Изменения сохраняются
в общей БД и доступны HR при следующей загрузке в рамках его прав.
Настройки Classic/RPG сохраняются через `/api/v1/me/preferences`.

## Данные

`public/data` содержит канонические синтетические `employees.json`, `events.json`,
`skills.json` и `activity_history.csv` с датой среза 2026-10-01. При запуске через
Compose с `DEMO_SEED=true` сервис `bootstrap` импортирует этот набор в PostgreSQL
и выдаёт демонстрационному HR доступ к его подразделениям. UI читает данные из
API, а эти файлы служат источником начального импорта.

Для дополнительных наборов используйте `POST /api/v1/admin/imports` либо
`uv run python -m career_quest.cli import` из папки `backend`.
Форматы, ограничения и примеры команд описаны в
[разделе импорта backend](../backend/README.md#импорт).
